Round 3, 2026-10-16. Decisions C-1 to C-5 (K/LANE.md §1, the r3 launch's C-2 / C-3) unchanged. Every number and name below is read from the file or command named beside it.

## (a) Transport = litert-samples `benchmark/ios` (worktree of upstream main 2db37a13)

- Archive (`build_xctest.sh`): `xcodebuild build-for-testing -destination generic/platform=iOS -derivedDataPath out/build -allowProvisioningUpdates DEVELOPMENT_TEAM=…`, then `zip -qrMM <out.zip> Release-iphoneos ./*.xctestrun BUILD_INFO -x "*.dSYM/*"` from `Build/Products`. The test bundle sits in the app's `PlugIns/`; the app's bundle id is read back from the manifest's `TestHostBundleIdentifier` (`run_ddp_ios.py read_archive`). The lab re-signs the app (litert-samples README step 4).
- Submit (`run_ddp_ios.py submit_args`): `gcloud beta device-run sessions submit xctest --device --test --other-files-to-push=SOURCE=BUNDLE:DEST,… --paths-to-pull=BUNDLE:PATH,… --xctest-timeout --xcode-version --labels --async`. gcloud 587 prints `[]` for `--async`; the session is found by the label `run=<uuid12>` in `sessions list`.
- Wait and pull: `sessions describe <id> --full` every 30 s until `sessionReport.status.statusType == DONE` (or `endTime`), cap = timeout + 20 min; then `gcloud storage cp -r <execution prefix>{artifacts,system.log,junit.xml}`. The pulled files sit flat under `artifacts/` (device path dropped): found by name.
- Limits (`gcloud beta device-run sessions submit xctest --help`, Cloud SDK 587.0.0): `--xctest-timeout` 1m to 1h, default 5m, "does not include any time necessary to prepare and clean up the target device"; `--device` is a device type and each type is one job (here 1 session = 1 device × 1 job); a push SOURCE is local (uploaded on every submit) or `gs://`; `--flaky-test-attempts` default 1 (kept); `--xcode-version` from `software-versions list`: `xcode-26-2` (default), `xcode-16-4`.
- Catalog (`gcloud beta device-run devices list`, 16:13): `iphone16pro-18-3` = displayName "iPhone 16 Pro", osVersion "18.3". `iphonese3-18-4` / `iphonese3-26-3` (4 GB) are out of scope.

## (d) The test's argv and the model

- `Documents/yardstick_args.json` = a JSON array of strings, the words `scripts/bench_matrix_iphone.sh run_cell` gives devicectl: `--yardstick-autorun --runtime litert-lm --model-id <id> --task short-chat --runs 4 [--context-tokens N] --litert-backend cpu|gpu`. The harness calls `HeadlessAutoRun.specFromLaunchArgs(["BenchmarkAppDDP"] + args)` (malformed values still `exit(2)` there, as in the app; the driver writes only known values).
- Model: pushed to `Documents/models/litert-lm/<repo with "/" as "__">/<file>` (`HFDownloader.modelDirectory`); `snapshot` returns it without a network call. Both Qwen3-1.7B ids share `litert-community__Qwen3-1.7B/`; `primaryFile` picks the file.
- Harness guards (lab code only): no args file → XCTFail with the Documents and container listings; not a string array, or no `--yardstick-autorun` → XCTFail; `--runtime` other than litert-lm → `YARDSTICK_FATAL runtime=<x> not_available` (2, the app's line); model file absent → `YARDSTICK_FATAL model_file_missing` (8) before any load, so the lab never downloads; a file pushed flat to `Documents/<file>` is moved into the model dir first.
- The runtime stays referenced after the run (as `AppSession` keeps it until `exit`): the engine is not torn down inside the test. The test asserts code 0 and at least `runs` new records; no `executionTimeAllowance` (the lab's `--xctest-timeout` is the cap).

## (g) Known risks and the sign of each

1. Re-signing drops the memory entitlements (C-5). Sign: Gemma E2B (2.59 GB) fails at load — `YARDSTICK_RUN_FAIL … Model load failed`, or a jetsam kill (no `yardstick.done`, junit crash) — while the 977 MB cell passes; failed runs keep their records. The archive's entitlements are checked at build (`codesign -d --entitlements -`: both present, r3/archive-check.txt); the lab's are not visible.
2. Push. Nested destination paths are unproven on the lab (litert-samples pushed into `Documents/` only; `devicectl copy to` creates them on the attached phone). Sign: session ERROR before the test, or `YARDSTICK_FATAL model_file_missing` (8); then `--flat-model-push` sends `/Documents/<file>` and the harness moves it in. Size: the largest push so far is a 14 MB .tflite; a 2.6 GB push that fails shows as a session ERROR with no test start.
3. Metal on the lab unit. Sign: the GPU cell's console lacks `RegisterAccelerator … name=GPU Metal` / `YARDSTICK_METAL_DEVICE name=Apple A18 Pro GPU`, or shows `Failed to create` for Metal → the GPU arm did not run (the CPU cells are unaffected).
4. Teardown (CLAUDE.md: litert cells can hang ~10 min at teardown). The runtime is kept alive, so the test returns; a hang at process exit would read as a job TIMEOUT / FAILED with `yardstick.done` = 0 and the records present (driver exit 4, records laid out).
