## 設計 memo(監督)
- `scripts/regression_watch.py [--summary results/summary/device-runs.csv] [--compare <P>/dist/regression.json] [--json out] [--markdown out]`: bench 側で P の規則どおりに赤を計算する(P の build_regression と同じ: REGRESSION_DEVICES = SM-S942Q / iPhone19,2 / Mac16,9 / Pixel 8a、models = Qwen 3 0.6B / Gemma 4 E2B、tasks = long-context-1024-gen256 / short-chat / native-benchmark、metrics = decode / prefill / mem_peak、閾値 = render_leaderboard.SPREAD_FLAG、admitted session のみ(SESSION.json)、campaign 名に dashboard、stand_in 行を除く、1 日 1 点 = latest_session、decode は同じ regime の前の点と比べる、engine_changed を持つ)。定義は `ops/autopilot/regression-watch.json` に(P の constants の写し + 出典行)。`--compare` で P の regression.json の赤の集合と一致を確かめる(受け入れ: 今の data で差 0)。
- 赤 1 点 → 再測の要求: `logs/dashboard-job/retakes.json`(状態 file、ignored)に {device key, cells row(cells file の行を byte-identical に), reason(metric, pct, prev campaign, engine_changed), created, status}。`dashboard_job.py` の `auto`: 選んだ device に pending の retake があれば **週次 set の前に** retake sitting を 1 本(生成 cells file = anchors の行 + retake の行; `--suffix retake-<slug>`; 通常の admission; docs §5「targeted retake」の自動化)。retake sitting の結果 → post(段 2)→ regression_watch を post の後に 1 回走らせる(red が残るか)。
- 赤が残り、prev の点と engine が違う → `logs/dashboard-job/bisect-requests.json` に {device, cell row, good = prev の engine label / bad = 今の engine label, verdict spec = `speed:decode<=-5%`(prefill 赤なら prefill)、route = ddp:<その device の lab 個体>(S26 → m1q-36、Pixel 8a → akita-35; iPhone / Mac = route なし → 要求だけ)} を書く。実行は `scripts/engine_bisect.py`(段 3b、branch bench-autopilot-bisect; この branch に無ければ「tooling not on this branch」と log して要求を残す = soft dependency)。
- profile: retake の cell が `native-benchmark-*`(litert_lm_advanced_main)で device が手元の Android(adb)なら retake sitting の中で `android/bench/run_profile.py` の対(control + profiled)を `<campaign>/profiles/` に(`./bench profile` の経路、docs/profiling-subcommand-design.md)。他の task / iOS / Mac / DDP = profile なし(1 行で理由)。
- issue の下書き: bisect の結果が出た時は engine_bisect.py が書く(段 3b)。bisect が無い時(route なし)でも `logs/dashboard-job/regression-<date>-<slug>.md` に EN + JA の下書き骨(数字、2 点の campaign、engine label、再現 command = `./bench dashboard-job <device> --cells <retake file>`)を書く。投稿は GO。
- selftest: 合成 summary + SESSION.json で赤の計算(regime 分け、1 日 1 点、engine_changed)、retake file の生成(byte-identical の行)、auto が retake を先に取る、bisect 要求の生成(route の有無)。CI step。
- 受け入れ: (1) `--compare` が P の dist/regression.json(P main 8100b64 の dist)と赤の集合で一致(今の bench main の summary で)。(2) 合成 data で赤 → retake → 要求の鎖が selftest で通る。(3) `dashboard_job.py auto --dry-run` が pending retake を先に印字(fake)。(4) docs/dashboard-autopilot-v1.md に段 3 の節。
