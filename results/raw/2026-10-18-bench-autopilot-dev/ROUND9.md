## 罠と袋小路

- Bash tool の zsh では `grep` が ugrep の関数 (`-P` が効く) だが、`bash script.sh` の中は `/usr/bin/grep` (BSD、`-P` なし) → ledger の確認が exit 3 になった (何も変えていない)。script では `awk -F'\t'` か `grep -E` を使う。
- 失敗した Xcode の build でも target の pre-build script は先に走る: MAIN の source の yardstick build は compile で落ちたのに、MAIN の `Vendored/engine-pins.json` を llama b11721 に書き換えていた (job の dd-mac は b8999 のまま)。build の後は成否に関わらず pins file を読み直す (元の値に戻した)。
- `ps | grep` で runner を探すと、他の agent の session の argv (settings の JSON) が当たる → program の path の先頭で絞るか pid で見る。
- `./bench matrix` = capture + build_summary + leaderboard: smoke でも走った tree の tracked な summary を書き換える → runner を直接呼ぶ。
- Mac runner は yardstick の出力の `tail -4` しか残さない → abort の frame は `~/Library/Logs/DiagnosticReports/yardstick-*.ips` で読む。
- PreToolUse の quiet hook は timing window が誰かに (自分の smoke にも) 取られている間 `python3 -c` を止める → grep で読むか、window の持ち主として `QUIET_OK=1`。
- b11721 の Android CPU tar は b10903 と launcher が同一: tool の sha だけの witness では build を分けられない (lib の hash で分ける)。
- 18 Pro の SIDE tree の SourcePackages (coreai-models 1.0 の依存を持つ) を seed にすると SIDE からの Mac の build は 2 分で通る。dd-mac-0180 の SourcePackages は MAIN の resolution (0.2.0) 用。
