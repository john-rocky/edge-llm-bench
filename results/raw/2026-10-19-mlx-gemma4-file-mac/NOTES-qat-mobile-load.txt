Why it does not load (read from the files):
- config.json has no `quantization` key, only `quantization_config`: quant_method "gemma", num_bits 4, and
  module_quant_configs (bits per weight): E2B (35 layers) lm_head 2, embed_tokens 2, embed_tokens_per_layer 4,
  mlp of layers 0-14 4 and of the other layers 2, self_attn 4, per_layer_input_gate / per_layer_projection 8,
  vision_tower 8, audio_tower 2 / 4; E4B (42 layers) lm_head 2, embed_tokens 2, embed_tokens_per_layer 2,
  every mlp 4, self_attn 4, per_layer_input_gate / per_layer_projection 8, vision_tower 8, audio_tower 2 / 4.
  Both Hub cards are frontmatter only (84 B, no quantization text).
- The safetensors header (E2B): each linear is weight U8 / I8 + weight_scale [out, 1] BF16 +
  input_activation_scale and output_activation_scale (scalars, BF16); embed_tokens is
  embedding_quantized U8 + embedding_scale BF16. That is Google's mobile schema (per-channel weights at
  2 / 4 / 8 bit, static activation scales), the schema ModelCatalog.swift's LiteRT-LM Gemma 4 entry
  describes ("wNa8o8 (int2/int4/int8 + int8 activations, QAT)"), not MLX's group-wise affine format
  (weight U32 + scales + biases).
- mlx-swift-lm 60bd0d7 reads the `quantization` key only (Libraries/MLXLMCommon/BaseConfiguration.swift,
  CodingKeys quantizationContainer = "quantization"); LLMModelFactory passes that per-layer quantization
  to loadWeights (Libraries/MLXLMCommon/Load.swift), so no layer is quantized, and
  Module.update(parameters:verify: .all) rejects the extra keys (E2B: weight_scale and the two activation
  scales) or the packed 2-bit lm_head's shape (E4B: [262144, 640] = 2560 columns at 2 bit, against
  [262144, 2560]).
