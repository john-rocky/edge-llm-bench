## 罠と袋小路

- The Mac quiet-window hook reads heredoc bodies: a scratch script written through a Bash heredoc that names the Python interpreter was stopped at 18:3x (`tapi-harness-r2c-speed` window). Write scratch scripts with the Write tool and call them by path.
- Another lane's windows came back in pieces (`t1c-qwen3-r2-gsm8k` from 18:19, 18:40, 18:53, 19:07): behind `quiet_wait.py` the regeneration waited 720 s, the adb-route selftest 645 s, the summary build 630 s. Queue every Mac-side step at once and wait on the done files.
- Counting IPv6 as "whatever `ipaddress` parses" counts C++ scopes (`d::f`) by the thousand; counting IPv4 the same way flags version strings shaped like dotted quads (`LOWI-9.0.1.132`, `oneconnect[1.8.51.30_01]`, `EasySetup[11.1.22.4]`: 8 distinct values in 852 m1q-36 lines) as global addresses and netmasks / 0.0.0.0 as private (Python's `is_private` covers 240/4 and 0/8). Count with the scrub's own prefixes and name the ranges (10/8, 172.16/12, 192.168/16).
- Samsung's star-masked MAC `aa:bb:cc:**:**:ff` slips past a six-pair hex rule and past the three-octet BSSID rule (a `:` follows the third octet): the MAC rule takes `*` as a pair character. A MAC right after a colon (`BSSID:aa:bb:…`) slips past r3's lookbehind `(?<![0-9A-Fa-f:])`: r4's refuses only hex and `*`.
- `ddp-raw/` keeps the bytes a logcat had before the first scrub that ran on it. For r2's two and 20 of r3's 48 per-run logcats that is the earlier rounds' scratch scrub, not the pull (their pulled bytes are in the bucket only; sha in ROUND2, `r3/pulled-logcat-sha256.txt`); the other 28 per-run copies and the 17 execution logcats' copies are the pulled bytes (sha equal).
- The first selftest run (18:50) failed one check of my own: `--records-only` exits 1 on the fixture campaign, as the billed run does there (the fixture's 1K runs are not clean: FAILURES.txt). The check now compares with the billed run's exit code.
- The DDP default cap wait is `run_cell.CPUCAP_WAIT`, which reads the env `CPUCAP_WAIT` at import (300 when unset); `cpucapWaitSeconds` in devices.json wins over both. With 0 the wrapper reads the caps once and records `cpucap_timed_out=1` on a capped unit, so `cpu-capped-at-start` stays.
- The id rule finds its keyword inside a word (`imei-less` names imei) and then takes every 10+-digit run of the line: a selftest keep line first drafted with `imei-less 12345678901` would have lost its number (reworded before the run).
- Left by the rules as written: `iccid=<4 digits>` in the m1q-36 logcats (17 lines in the execution logcats, 6 in the per-run ones; the digits do not start with 89, the ICCID prefix); the id rule takes 10+ digits only. Widen it if a 4-digit fragment counts.
